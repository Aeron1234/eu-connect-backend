# Prepare the VPS

Commands in this folder run in a Linux SSH shell. Obtain the school's approval for its production server changes. Use a fresh Ubuntu 24.04 LTS image for this reference procedure. Existing OpenLiteSpeed/Apache/CloudPanel installations require adaptation before installing another web server.

## Host and operator access

Create an administrator with SSH-key access and sudo rights through the school's normal procedure. Test that login in a second session before restricting root or password login. Record emergency access through Hostinger's console.

```bash
sudo apt update
sudo apt upgrade
sudo apt install -y nginx git curl ca-certificates xz-utils openssl ufw
sudo timedatectl set-timezone Asia/Manila
timedatectl
sudo adduser --system --group --home /srv/eu-connect --shell /bin/bash euconnect
sudo install -d -o euconnect -g euconnect -m 750 /srv/eu-connect/releases /srv/eu-connect/shared
```

Install a verified official Node 24.x Linux binary or use the school's maintained Node package source. Check the selected version's checksum/signature against Node's release files. Put node at /usr/local/bin/node or edit both supplied unit files to the actual absolute executable. Ensure npm is on the build user's PATH. Avoid a root user's private version-manager directory for a system service.

```bash
/usr/local/bin/node --version
npm --version
sudo -u euconnect /usr/local/bin/node --version
```

Confirm the installed version satisfies >=24.22.3 <25. Node 26 currently requires an application compatibility decision because it falls outside the manifests' declared range.

## Firewall

Before enabling UFW, allow the actual SSH port used by the school. OpenSSH below assumes the default port 22. Hostinger's network firewall and the guest firewall must both permit the intended traffic.

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
sudo ufw status verbose
```

Allow 80/443 publicly and restrict SSH to school operator IPs where practical. Keep ports 3000, 7000 and a local database's 3306 closed publicly, including IPv6. The backend currently calls listen(PORT) without a loopback host, so firewall enforcement is required. The frontend unit explicitly binds 127.0.0.1.

## Source releases

Export or clone the approved frontend/backend commits into releases/RELEASE_ID/frontend and backend, preserving package-lock.json. Use private deploy credentials with read-only repository access. Review each release pair and record its commit hashes.

Exclude developer .env files, Windows node_modules, .next, coverage, work/, copies/, editor state and database dumps from upload. Keep tests and migration history in a controlled source checkout, even when runtime packaging excludes them. public/pdfjs is generated by the frontend build hook. Keep active public assets and public/avatars.

Run build/install as euconnect, with write access to its release and browser cache. Root performs package installation, systemd, Nginx and certificate administration. Keep production credentials under shared/ with mode 600 and owner euconnect. Populate them through a secure editor or secret-management workflow; examples contain no real credentials.


## Initialize the first release

Have the administrator create releases/REPLACE_RELEASE_ID with frontend/ and backend/ owned by euconnect, then export the two approved repositories there. Copying sources must preserve imports, manifests, active public files and build inputs. Use a release ID without spaces.

```bash
sudo install -d -o euconnect -g euconnect -m 750 /srv/eu-connect/releases/REPLACE_RELEASE_ID/frontend /srv/eu-connect/releases/REPLACE_RELEASE_ID/backend
# Populate the directories and perform the backend/frontend preparation steps first.
# Run once when current does not already exist:
sudo ln -s /srv/eu-connect/releases/REPLACE_RELEASE_ID /srv/eu-connect/current
```

Check ownership after copying files. Link both environment files from shared/ into their respective release folders. If using git clone, clone into the empty frontend/backend directories as euconnect. Give its deploy key only the required read access. Do not place a token directly in a clone URL saved in shell history.

After both units have been copied into /etc/systemd/system, reload the service definitions. During later deployments a changed unit requires another daemon-reload; source-only updates require restarting the applications.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now eu-connect-backend
sudo systemctl enable --now eu-connect-frontend
```

Use the official [Node installation/download page](https://nodejs.org/en/download) to select the current supported, patched Linux x64 build within Node 24. Verify its signed checksums and confirm the installed executable path matches the units. The versions available in Ubuntu's default package repository may differ from the manifests' required range.
